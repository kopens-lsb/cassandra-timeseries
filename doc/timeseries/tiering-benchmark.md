# 계층화 전/후 실측 — 운영 테이블 형태

계층화를 켜기 전과 후를 **같은 이미지·같은 노드 설정·같은 데이터·같은 CQL**로 측정한 결과입니다.
스크립트: [`docker/scale-test.sh`](../../docker/scale-test.sh)(베이스라인) ·
[`docker/tiering-bench.sh`](../../docker/tiering-bench.sh)(계층화). 원자료:
[베이스라인](tiering-bench-baseline.md) · [계층화 후](tiering-bench-tiered.md).

## 측정 조건

| 항목 | 값 |
| --- | --- |
| 테이블 형태 | `tm_tag_point` — 파티션 키 `tag_id`, 클러스터링 `timestamp DESC`, static 7개, 일반 컬럼 8개 |
| 행 수 | **30,000,000** |
| 태그(파티션) | **600개**, 태그당 **50,000행** = 1초 간격 13.9시간 |
| 값 컬럼 | static `type`이 어느 컬럼을 채우는지 결정 — 숫자형 태그는 `value_numeric`, boolean 태그는 `value_boolean`, `value`(text)는 판독값의 문자열 사본 |
| 집계 컬럼 | **`value_numeric`** (`type='double'` 태그) — 실제 대시보드가 집계하는 컬럼 |
| 상수 컬럼 | `quality`=192, `error_code`=0, `attribute`={} — 운영 실측 그대로 |
| 정책 | `hot_window 1h`, `chunk_window 1h` — 전 구간을 콜드로 만든 **최대 부하** 조건 |
| 노드 | 단일 노드, Generational ZGC, 힙 16G, `gc_grace_seconds=0` + 메이저 컴팩션으로 톰스톤 실회수 |

> **밀도를 밝히지 않은 행당 바이트는 의미가 없습니다.** 행이 몇 개 없는 창은 대부분 헤더입니다.
> 위 밀도(태그당 5만 행, 창당 3,600행)가 아래 모든 수치의 전제입니다.

## 질의 시간

같은 CQL, 같은 결과값. 비율은 `전 ÷ 후` — 1보다 크면 계층화가 빠릅니다.

### 집계 — 계층화가 빠릅니다

| 질의 (단일 파티션, 50,000행) | 전 | 후 | 비율 |
| --- | --- | --- | --- |
| `time_bucket 1h + avg/min/max` | 412 ms | **189 ms** | **2.18×** |
| `time_bucket 5m + avg` | 577 ms | **241 ms** | **2.39×** |
| `first`/`last`/`delta`/`rate` per hour | 509 ms | **214 ms** | **2.38×** |
| `derivative` per hour | 344 ms | **159 ms** | **2.16×** |
| `percentile` p50/p95/p99 | 419 ms | **174 ms** | **2.41×** |
| `variance`/`stddev` | 296 ms | **156 ms** | **1.90×** |
| `histogram` 20버킷 | 301 ms | **190 ms** | **1.58×** |
| `approx_count_distinct` | 332 ms | **151 ms** | **2.20×** |
| `OHLC + change + p95` (대시보드 종합) | 526 ms | **352 ms** | **1.49×** |
| `count(*)` (파티션 내) | 333 ms | 346 ms | 0.96× |
| `integral + time_weighted_average` | 4,970 ms | 4,666 ms | 1.07× |

| gap-fill | 전 | 후 | 비율 |
| --- | --- | --- | --- |
| `gapfill 1h + locf` (13.9h 전 구간) | 597 ms | **143 ms** | **4.17×** |
| `gapfill 5m + interpolate` (6h) | 201 ms | **46 ms** | **4.37×** |

| 멀티 파티션 | 전 | 후 | 비율 |
| --- | --- | --- | --- |
| 10개 태그 시간별 avg (50만 행) | 4,429 ms | **1,904 ms** | **2.33×** |
| 100개 태그 시간별 avg (500만 행) | 36,265 ms | **17,282 ms** | **2.10×** |
| 100개 태그 태그별 p95 (500만 행) | 34,223 ms | **15,349 ms** | **2.23×** |

빨라지는 이유는 스캔량입니다 — 5만 행을 SSTable에서 훑는 대신 창당 청크 하나를 읽어 디코드합니다.
데이터가 4.9× 작아지므로 IO·역직렬화가 지배적인 집계에서 그대로 이득이 됩니다.

### 행 단위 조회 — 계층화가 느립니다

집계와 정반대입니다. 청크는 **창 단위로 디코드**되므로 행 몇 개만 원하는 질의도 창을 통째로 풉니다.

| 질의 | 전 | 후 | 비율 |
| --- | --- | --- | --- |
| 최신 1,000행 `SELECT *` (boolean 태그) | 60 ms | 212 ms | **0.28× (3.5배 느림)** |
| 최신 1,000행 `SELECT *` (double 태그) | 53 ms | 167 ms | **0.32× (3.1배 느림)** |
| **static 컬럼만 1행** | 3 ms | 95 ms | **0.03× (31배 느림)** |
| 1시간치 `SELECT *` (3,600행) | 213 ms | 199 ms | 1.07× |
| 1시간치 `timestamp+value`만 투영 | 55 ms | **40 ms** | 1.38× |

**static 컬럼만 읽는 질의의 31배 저하**가 가장 두드러집니다. static은 애초에 청크화되지 않아
디코드할 것이 없는데도 콜드 경계 판정과 청크 조회를 거칩니다. 태그 메타데이터를 자주 조회한다면
투입 전에 확인하십시오.

## ⚠️ 파티션 키 없는 집계는 0을 돌려줍니다

| 질의 | 전 | 후 |
| --- | --- | --- |
| `SELECT count(*)` (파티션 키 없음) | 184,007 ms → `30000000` | **53 ms → `0`** |

**가속이 아니라 오답입니다.** 레인지 스캔은 청크를 병합하지 않으므로, 전부 계층화된 테이블에서
파티션 키 없는 집계는 부분 결과가 아니라 **아무것도 못 봅니다**. 클라이언트 경고가 나가지만 대부분의
드라이버는 노출하지 않습니다. 투입 전 애플리케이션 점검 항목입니다 —
[프로덕션 체크리스트](production-rollout.md).

## 해석

이 형태에서 계층화는 **저장과 집계 양쪽에서 이깁니다** — 디스크 4.9×, 집계 약 2×, gap-fill 4×.
컬럼이 여럿이고 그중 상당수가 상수이거나 전부 null인 구조(`quality`·`error_code`·`attribute` 고정,
static `type`에 따라 `value_numeric`/`value_boolean` 중 하나가 통째로 빔)에서 컬럼 지향 청크가
설계 의도대로 동작한 결과입니다.

대가는 **행 단위 조회**입니다. 최신 N행을 통째로 꺼내는 패턴은 3배 느려집니다. 조회가 집계 중심이면
이득이 크고, 원시 행을 그대로 퍼가는 패턴이 많으면 손해입니다.

> **`hot_window` 안쪽 질의는 비용이 없습니다.** 질의 범위가 콜드 경계 위에서 시작하면 병합 자체를
> 건너뛰고 핫 이터레이터를 그대로 돌려줍니다. 위 수치는 `hot_window 1h`로 **전 구간을 콜드로 만든**
> 최대 부하 조건입니다. 실제 운영에서 `hot_window`를 대시보드 구간에 맞추면 그 구간 질의는 계층화
> 전과 동일합니다.

## 형태에 따라 결과가 크게 다릅니다

같은 코드로 `(series text, ts timestamp, value double)` — **고엔트로피 double 컬럼 1개**짜리 형태를
재면 디스크 35% 절감에 질의는 동률~30% 느림이 나옵니다. 접을 상수 컬럼도, 비울 null 컬럼도 없어
컬럼 지향 포맷의 이득이 전혀 발생하지 않기 때문입니다.

**계층화의 이득은 "컬럼이 여러 개이고 그중 상당수가 반복적인가"에 달려 있습니다.** 산업 현장의
태그 테이블은 대체로 그렇지만, 도입 전 자기 테이블 형태로 재보는 편이 확실합니다.
